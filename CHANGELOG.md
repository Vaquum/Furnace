# v0.17.2

- Fix a stopped round hanging forever on `terminating`. When a round was terminated, `run_round.py` — which had no signal handler — was killed by the same process-group signal that stopped the round, so it died before its `limen run` child and orphaned limen onto the container's PID 1. The experiment_runner server *is* that PID 1 and has no code to reap orphans, so once limen exited it became a zombie; a zombie still counts as a member of its process group, so `os.killpg(pgid, 0)` kept succeeding and the round's watcher never flipped it `terminating → terminated`. The terminate endpoint also gave limen only 5 seconds before `SIGKILL`, cutting short limen's cooperative shutdown — the checkpoint write that makes a round resumable. `run_round.py` now supervises the `limen run` child: it catches the stop signal, forwards it to limen, and stays alive in `proc.wait()` to reap limen itself, so limen is never orphaned. The terminate endpoint signals `run_round.py` and returns immediately; limen runs its full cooperative shutdown — finish the in-flight permutation, write a resumable checkpoint, finalize — and a daemon backstop `SIGKILL`s the process group only if limen never exits. The deploy container additionally runs an init process (`init: true`) so an orphan from limen's own multiprocessing children is reaped too.

# v0.17.1

- Fix the round-status progress and stats sitting dead for the whole run. In v0.16.0 `limen run` wrote each round's artefacts into a timestamped `results/<name>_<datetime>/` directory that `run_round.py` relocated to `<round>/limen_output/` only after the run finished — so the round page's progress counter stayed at `0` and the stats table stayed empty until the round completed. The round-status poll reads that file as it grows, so the top-bar progress and the stats distribution climb live as permutations complete. `run_round.py` no longer relocates anything, and fails loud if a round's manifest does not direct output to `limen_output/`.

# v0.14.0

- Adapt the experiment_runner UI to Limen's new decoder-level metric ledger from `vaquum_limen` PR #520 (>= 3.2.1). The Limen change replaces the old scalar backtest surface (`backtest_total_return_net_pct`, `backtest_sharpe_per_bar`, `backtest_max_drawdown_pct`, `backtest_mean_kelly_pct`, `backtest_trades_count`, `backtest_bars_total`, `backtest_bars_in_market_pct`) with a 22-column ledger: 7 distribution metrics each at p5 / p50 / p95 (`edge_per_signal_bps`, `trade_pnl_net_bps`, `cost_drag_bps`, `rolling_return_net_bps`, `return_on_exposure`, `drawdown_depth_bps`, `drawdown_duration_days`) plus one scalar (`cvar_95_return_bps`). All ship into the round CSV with the `backtest_` prefix. Without this adapter the results table, round-status stats panel, and cross-round search index reference columns that no longer exist; the table silently truncates to id + confusion metrics and the search index refuses to build (its `_SEARCH_REQUIRED_COLS.issubset(df.columns)` check fails on every post-3.2.1 round).
- All three surfaces now expose the same metric set so they stay in sync — `id` + 4 confusion / precision (`precision`, `recall`, `confusion_tp_mean_return_pct`, `confusion_fp_mean_return_pct`) + the 22 ledger columns. The results table renders the columns in that order; the round-status stats panel computes cross-permutation p5 / p25 / p50 / p75 / p95 for each metric and updates live as the round writes permutations; the search page exposes each metric as a range slider for cross-round filtering.
- `_ensure_round_index` no longer divides metrics by `backtest_bars_total` to derive `*_per_bar` proxies — the new ledger emits values already scaled to per-signal / per-trade / per-day / fraction units, so the indexer reads each metric column straight from the CSV with a single cast pass. The single source of truth is `_BACKTEST_LEDGER_COLUMNS` at the top of the module; the three downstream lists (`_RESULTS_COLUMNS`, `_compute_round_stats` desired, `_SEARCH_METRICS`) splat it in, so future Limen ledger additions are a one-line tuple edit.
- A round indexed for search must carry every metric the search page filters on, so pre-3.2.1 rounds (whose CSV has the retired scalar surface but none of the new columns) are skipped from the cross-round index until they are re-run on a Limen that emits the new ledger. The results table and round-status panel are tolerant — they pick whichever columns the CSV actually carries — so the legacy CSVs still render their confusion / precision rows.

# v0.6.0

- Protect every runtime endpoint with HTTP Basic + Bearer-token auth. Browser users authenticate via HTTP Basic against `APP_USERNAME` / `APP_PASSWORD` (e.g. `curl -u user:pass http://host/...`); programmatic API consumers send `Authorization: Bearer <API_SECRET>`. The middleware accepts both schemes case-insensitively per RFC 7235 (so `bearer <token>` works alongside `Bearer <token>`). Without auth, every JSON, HTML, log, and bundle route returns `401` with `WWW-Authenticate: Basic realm="experiment_runner"`. Three exemptions: the new `/health` endpoint (used by the compose healthcheck), the `/static/*` mount (CSS/JS — not sensitive), and the existing `HEAD /` smoke check from slice S02 (kept public so the operator's `curl -sI` still works). The runner refuses to start (`RuntimeError`) if any of the three env vars is unset — there is no "no auth" mode. The deploy workflow plumbs the secrets from repo settings (`secrets.APP_USERNAME`, `secrets.APP_PASSWORD`, `secrets.API_SECRET`) through to the compose `.env` on the TDW host so the container reads them at startup, with a fail-fast guard rejecting any secret value that contains a newline (which would corrupt `.env` line-orientation). The compose healthcheck moves from `GET /` to `GET /health` so the unauthenticated probe still works after this change.

# v0.5.1

- Migrate all `TemplateResponse(...)` calls in `experiment_runner/app.py` to the starlette 1.0 signature (`request` is now the first positional arg). The previous old-style `(name, context)` form was a silent runtime failure on starlette 1.0.0+: the template name was being read as `request` (a string), the context dict was being read as `name`, and the unhashable dict propagated into jinja2's template cache as `TypeError: unhashable type: 'dict'` — every HTML page returned 500 (jobs page, experiment page, search page, round page, results page, and the `_partials/*` rows). Pin `starlette>=1.0.0` in `experiment_runner/requirements.txt` so the contract is explicit at install time.
